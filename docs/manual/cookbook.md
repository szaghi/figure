# Cookbook

One task per recipe. Every snippet is part of a program in
[`docs/examples/src`](https://github.com/szaghi/figure/tree/main/docs/examples/src), compiled against the library by
`docs/examples/build.sh`; the outputs shown are those of the headless programs, regenerated by the same script.

## The loop

### Refresh data that changes on its own

<<< @/examples/snippets/cb_refresh-refresh.F90{fortran}

When the data changes outside the program's frame loop (the clock here; a log file written by another process; a
value updated by another thread), nothing tells the loop to draw. `max_wait` is the longest the idle loop sleeps:
the data is shown at most `max_wait` seconds late. The default is 0.5 s; a longer period costs less while idle
([what idle costs](/guide/frame-loop#what-idle-costs)).

### Redraw continuously

<<< @/examples/snippets/cb_continuous-continuous.F90{fortran}

`set_lazy(.false.)` draws a frame per loop iteration, whatever the input. With `vsync` on (the default) the rate is
the display's; with `vsync=.false.` the loop runs as fast as the machine draws. Both cost CPU (and GPU) while idle: for
an animation that runs only some of the time, prefer [`request_frames`](/manual/tutorial/04-live).

<<< @/examples/snippets/cb_time-time.F90{fortran}

animation takes its position from the clock, so it keeps its speed at any frame rate:

### Draw only the rows in view

<<< @/examples/snippets/cb_tree-large.F90{fortran}

A list of 20000 rows costs a frame what the rows in view cost when a `list_clipper_object` draws them: `call
clip%begin(n)`, then `do while (clip%step())` draws rows `clip%first` to `clip%last`, and the loop ends by itself. The
rows are of equal height (lines of text, selectables, a table's rows, leaf nodes); the clipper measures the first one
(`clip%item_height`, in pixels). Here the 20000 children of one tree node are clipped in a region of their own
(`ig_begin_child`), between the node and its `ig_tree_pop`: a whole tree with nodes open in the middle is not a run of
equal rows ([Trees](/guide/widgets#trees) shows how to flatten one).

A row the clipper did not draw is no item on that frame: nothing scrolls to it and nothing extends from it. The
program reaches it by its place, `(i - 1) * clip%item_height` below the top ([Reveal an item picked
elsewhere](#reveal-an-item-picked-elsewhere)), and keeps one row drawn wherever it is with `clip%begin(n, keep=k)`: the
row a shift+click extends from, `sel%keep` ([Select many rows at once](#select-many-rows-at-once)). [The table below](#a-sortable-table-with-a-fixed-header)
clips its 200 rows the same way. [Lists and regions](/guide/widgets#lists-and-regions) has the rules.
