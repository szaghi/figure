# Cookbook

One task per recipe. Every snippet is part of a program in
[`docs/examples/src`](https://github.com/szaghi/figure/tree/main/docs/examples/src), compiled against the library by
`docs/examples/build.sh`; the outputs shown are those of the headless programs, regenerated by the same script.

[[toc]]

## The loop

### Refresh data that changes on its own

<<< @/examples/snippets/cb_refresh-refresh.F90{fortran}

When the data changes outside the program's frame loop (the clock here; a log file written by another process; a
value updated by another thread), nothing tells the loop to draw. `max_wait` is the longest the idle loop sleeps:
the data is shown at most `max_wait` seconds late. The default is 0.5 s; a longer period costs less while idle
([what idle costs](/guide/frame-loop#what-idle-costs)).

### Redraw continuously

<<< @/examples/snippets/cb_continuous-continuous.F90{fortran}

`set_lazy(.false.)` draws a frame per loop iteration, whatever the input. With `vsync` on (the default) the rate is
the display's; with `vsync=.false.` the loop runs as fast as the machine draws. Both cost CPU (and GPU) while idle: for
an animation that runs only some of the time, prefer [`request_frames`](/manual/tutorial/04-live).

### Size in proportion to the display scale

<<< @/examples/snippets/cb_scale-scale.F90{fortran}

`init` creates the window `content_scale()` times larger than asked and scales the Dear ImGui style; the sizes the
program passes are not scaled. Multiplying them by `content_scale()` keeps their proportion to the window on high-DPI
displays.

### Contour lines over a field

<<< @/examples/snippets/cb_contour-contour.F90{fortran}

`ip_contour` takes the positions of the first and last samples; a heatmap takes the outer edges of its cells: give it

### Plot the rows of a matrix

A row of a column-major matrix is strided. When its abscissae are uniform, `ip_line(label, y, row [, xscale]
[, xstart])` plots it in place: ImPlot reads `y(row, j)` with a stride of `size(y, 1)` elements, no copy at all.

<<< @/examples/snippets/cb_rows-rows.F90{fortran}

With arbitrary abscissae there is no in-place form: ImPlot applies one stride to both `x` and `y`, so a contiguous
`x` and a strided row cannot be read together. Passing the section `history(i, :)` makes the compiler copy it into a
temporary at every call (allocated and freed each frame); copying it yourself into a buffer allocated once costs the
same copy without the allocation. Storing series as columns avoids the question.

<<< @/examples/snippets/cb_rows-rows-copied.F90{fortran}

<Media name="cb_rows" :width="620" alt="Three plots of the same two probes: columns read in place, rows read in place with a stride, rows copied" caption="docs/examples/src/cb_rows.F90: the three ways give the same plot" />

## Running work

### Run a tool and show its output

<<< @/examples/snippets/cb_process-run.F90{fortran}

<Media name="cb_process" video alt="Run is clicked: the tool prints a solver's log of 120 iterations into the log view, which follows the end; the status line then reads ended, exit code 0" caption="docs/examples/src/cb_process.F90" />

The tool's arguments are an array, without a shell. Its output is read by FIGURE as the tool writes, so the window
keeps answering and the tool never waits for the program; every frame the program takes the complete lines
(`poll`) and adds them to a log view, which draws only the lines in view and follows the end while it is scrolled to
the bottom. Stop asks the tool to end; a tool still running when the program ends is stopped. A run that must outlive
the program is started `detached=.true.` with a `log_file`. [Processes and tasks](/guide/processes) has the details.

Used in context: [chapter 11](./tutorial/11-run) of the tutorial.

### Read a large file without freezing the window

<<< @/examples/snippets/cb_task-work.F90{fortran}

<<< @/examples/snippets/cb_task-ui.F90{fortran}

<Media name="cb_task" video alt="Read is clicked: a task reads a field of two million values block by block, its progress shown as a percentage and the block; then the number of values, the minimum, maximum and mean" caption="docs/examples/src/cb_task.F90" />

The reading runs as a task, on a thread of its own: the window keeps drawing, in remote mode the browser keeps
receiving frames. The task opens its own unit, reports after each block and checks `h%cancelled()` there, so Cancel
stops it between two blocks with consistent statistics. Every frame the program shows the progress; once the task is
done it takes the result, once. The task never draws: [the threading rule](/guide/processes#tasks).
