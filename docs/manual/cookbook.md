## The loop

### Refresh data that changes on its own

<<< @/examples/snippets/cb_refresh-refresh.F90{fortran}

When the data changes outside the program's frame loop (the clock here; a log file written by another process; a
value updated by another thread), nothing tells the loop to draw. `max_wait` is the longest the idle loop sleeps:
the data is shown at most `max_wait` seconds late. The default is 0.5 s; a longer period costs less while idle
([what idle costs](/guide/frame-loop#what-idle-costs)).

### Redraw continuously

<<< @/examples/snippets/cb_continuous-continuous.F90{fortran}

`set_lazy(.false.)` draws a frame per loop iteration, whatever the input. With `vsync` on (the default) the rate is
the display's; with `vsync=.false.` the loop runs as fast as the machine draws. Both cost CPU (and GPU) while idle: for
an animation that runs only some of the time, prefer [`request_frames`](/manual/tutorial/04-live).

### Size in proportion to the display scale

<<< @/examples/snippets/cb_scale-scale.F90{fortran}

`init` creates the window `content_scale()` times larger than asked and scales the Dear ImGui style; the sizes the
program passes are not scaled. Multiplying them by `content_scale()` keeps their proportion to the window on high-DPI
displays.

## Windows

### Pair begin and end, skip what is hidden

<<< @/examples/snippets/cb_hidden_window-pairs.F90{fortran}

- `ig_end` follows every `ig_begin`; `ip_end_plot` follows only an `ip_begin_plot` that returned `.true.`.
- A collapsed window returns `.false.`: the expensive part (here, 100 000 evaluations) is skipped with its content.

## Plots

### Plot the columns of a matrix

<<< @/examples/snippets/cb_rows-columns.F90{fortran}

A column of a Fortran array is contiguous: ImPlot reads it in place.

### Combine items and styles in one plot

<<< @/examples/snippets/cb_items-spec.F90{fortran}

<<< @/examples/snippets/cb_items-items.F90{fortran}

Items are drawn in call order: put shaded areas first so the lines stay visible. A spec built once outside the loop
costs nothing per frame; one built inline (`spec=ip_spec(...)`) is rebuilt every frame, which is cheap but not free.
The `x(::5)` sections are not contiguous: the compiler copies them (see the next recipe).
[Plots](/guide/plots#item-style) lists every `ip_spec` argument.

### Show a field and its colour scale

<<< @/examples/snippets/cb_field-heatmap.F90{fortran}

<Media name="cb_field" alt="A heatmap of a Gaussian bump with a colour bar, an image drawn inside the plot and the same image as a widget" caption="docs/examples/src/cb_field.F90: a heatmap with its colour scale, and an image as a plot item and as a widget" />

`f(i, j)` is read in place, `i` along x and `j` along y, `j = 1` at the bottom; the bounds are the outer edges of the
cells. Fix the scale (`scale_min`, `scale_max`) when the field changes over time, or the colours rescale every frame.

### Show an image computed by the program

<<< @/examples/snippets/cb_field-texture.F90{fortran}

Upload once, draw every frame: `tex%update` only when the pixels change (a new iteration of a computation), `ig_image`
or `ip_image` in the loop.

### Plot the rows of a matrix

A row of a column-major matrix is strided. When its abscissae are uniform, `ip_line(label, y, row [, xscale]
[, xstart])` plots it in place: ImPlot reads `y(row, j)` with a stride of `size(y, 1)` elements, no copy at all.

<<< @/examples/snippets/cb_rows-rows.F90{fortran}

With arbitrary abscissae there is no in-place form: ImPlot applies one stride to both `x` and `y`, so a contiguous
`x` and a strided row cannot be read together. Passing the section `history(i, :)` makes the compiler copy it into a
temporary at every call (allocated and freed each frame); copying it yourself into a buffer allocated once costs the
same copy without the allocation. Storing series as columns avoids the question.

<<< @/examples/snippets/cb_rows-rows-copied.F90{fortran}
