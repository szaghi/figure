# The Fortran path's code editor and diff (szaghi/figure#15 P16)

The seam is `figure_editor` as a whole: `code_editor_object`, `language_object`, `code_language`, `code_diff`,
`code_diff_lines`. Its current implementation, `src/paths/imgui/editor/figure_editor.F90`, is a thin layer over the
native glue's entry points (`fig_editor_*`, `fig_code_diff*`: `native/figure_editor.cpp`, over ImGuiColorTextEdit, the
goossens fork with FIGURE's two patches, and dtl). The Fortran editor gives the same entry points, with the glue's names,
arguments, statuses and messages, as Fortran module procedures (`figure_code_editor`, `figure_code_view`,
`figure_code_diff`). Since the seam's switch the Fortran path's `figure_editor` is here (`figure_editor.F90`): the
current path's module with its interface block replaced by `use` statements of those modules, written by
`scripts/gen_editor_path.py`, so the two never differ in an argument check, a status, a message or a doc comment
(`check_sync.py` checks it is current); `$PATH_FORTRAN` takes it in place of src/paths/imgui/editor/. Its tests
(`src/tests/fortran/figure_test_code_editor_*.F90`) drive the current path's through `figure_editor_ref` (that module
under another name, generated by `scripts/gen_implot_ref.py`) and the Fortran one in one program.

The editor is the fork's `TextEditor` as FIGURE's glue configures it: no blanks shown, no pairs completed, no
mini-map, no pan indicator, a decoration column of two glyphs (the marks' icons), completion by the program's words.
The fork's features the glue never turns on (line folding, word wrap and its Unicode line breaking, squiggles, user
data, the change callbacks, custom carets and line numbers) are left out.

Progress, and what is left, are tracked on [#15](https://github.com/szaghi/figure/issues/15) (P16), not here.

## Modules

- `figure_code_unicode_tables` (generated by `scripts/gen_editor_tables.py` from `TextEditor.cpp`): the fork's 16-bit
  code-point tables (FIGURE builds Dear ImGui with 16-bit `ImWchar`).
- `figure_code_unicode`: `TextEditor::CodePoint`: UTF-8 read and written as the fork does (U+FFFD for a sequence cut
  short or of four bytes), letters, numbers, white space, words, case, glyph widths. StringiFor's Unicode 17.0 tables
  are not used here: they classify some code points otherwise than the fork's, and the editor's words, columns and case
  changes must be the fork's.
- `figure_code_document`: `Document`, `Cursor`, `Cursors`, `Transactions`: lines of glyphs (code point, colour,
  columns) with room to grow, positions as the fork's `DocPos` (from 0), the cursors sorted and merged as the fork's,
  the undo list flat (every transaction's actions, texts and saved cursors in pools cut at the undo index).
- `figure_code_language`: `Language` and `Colorizer`: a registry of languages (one per packed definition, one per fork
  language), keyword sets searched by bisection, an identifier spelt into a fixed buffer (no allocation), FIGURE's own
  tokenizers (identifiers, numbers with Fortran's kinds and exponents, ASCII punctuation, key = value lines), the
  fork's languages' (C's identifiers and punctuation, Julia's tokenizers by hand; the rest generated), the comment
  and string levels (Lua's long brackets).
- `figure_code_languages_fork` (generated by `scripts/gen_editor_languages.py` from the fork's language files): the
  re2c state machines translated state for state, each language's definition and keyword sets.
- `figure_editor` (generated by `scripts/gen_editor_path.py`): the public API over the Fortran editor.
- `figure_code_editor`: the editor (the fork's operations: insert and delete through transactions, find, replace,
  markers) and the glue's entry points (`fig_editor_*`): marks with severities from their colour, completion words, the
  word at the cursor.
- `figure_code_view`: the editor drawn: the glue's `fig_editor_draw` (the style's palette, IBM Plex Mono, a bordered
  child window) and `fig_editor_line_rect`; the fork's `render` in its order, `updateState`, the type setter (a row a
  line), the bracketeer, the scroll requests; the keys and the mouse (`handleKeyboardInputs`,
  `handleMouseInteractions`) with the edits and moves they make; the completion popup (the glue's suggestions) and
  the find and replace window. It draws through `figure_core_text` (`src/paths/imgui/core/`, the inner
  seam's calls for the editor, `ct_*`).
- `figure_code_diff`: dtl's `Diff::compose` (the O(NP) shortest edit script of two texts' lines) and the glue's
  `fig_code_diff_lines`; the fork's `TextDiff` (one column and side by side, their scroll bars and the changes on the
  vertical one) and the glue's `fig_code_diff` (a diff kept per id, forgotten after 600 frames not drawn).

## Tests

`src/tests/fortran/figure_test_code_editor_*.F90`, built by the `-fortran` modes: the same calls of FIGURE's public API
on `figure_editor_ref`'s `code_editor_object` (C++) and `figure_editor`'s (Fortran), compared after each call.
`_text`: the text, cursors, selections, marks, find, replace, undo and redo, statuses and messages, scripted and over
1500 random calls (texts with tabs, CR LF, two- and three-byte UTF-8, a wide glyph, sequences cut short); the lines
`code_diff_lines` reports for 400 random pairs of texts. `_draw`: both editors drawn by the same calls in a window at
the same place, each frame's draw result, cursor, selection and lines' rectangles to the bit, the last pictures at
threshold 2 with no pixel failing (marks and their tooltips, focus and the caret, brackets, selections, white space,
tabs, wide glyphs, scrolling, the light palette, options). `_input`: the same scripted keys, characters, clicks, drags,
middle button and wheel played to both editors, each frame's text, cursor, selection and rectangles to the bit, the
last pictures equal. `_popups`: the same for the completion popup (its words every frame) and the find and replace
window, two pictures per case. `_diff`: `code_diff` by both, pictures equal, scrolled by the keys and the wheel. `_languages`: the 13 fork languages
and FIGURE's coloured by both, pictures equal.
