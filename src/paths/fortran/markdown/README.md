# The Fortran path's Markdown seam (szaghi/figure#15 P15)

The Markdown seam is `figure_markdown` (`ig_markdown`, `markdown_view_object`). The current path's, over
imgui_rich_md (C++, vendored in third_party/imgui_rich_md with md4c), is `src/paths/imgui/markdown/figure_markdown.F90`
with its glue in `native/figure_markdown.cpp`; the Fortran path's is here, with the same public API, statuses and
messages, drawn by imgui_rich_md's renderer and documents in Fortran. md4c, the parser, stays C (the ADR's K1):
`figure_md4c` binds its C API, and the renderer is called back as md4c enters and leaves each block and span.

They draw through figure_core only, with imgui_rich_md's calls in its order: the layout and widgets a Markdown text is
made of (a text run and its open line, indents, groups, tables, child windows, collapsing headers, fonts with their
size, tooltips, popups, tab bars, combos, the find field) are `figure_core_layout` (`cl_*`, src/paths/imgui/core/),
whose sizes are single precision as Dear ImGui's, so the renderer's arithmetic is imgui_rich_md's and its layout the
same to the bit. The fonts are loaded as imgui_rich_md loads its own (`fig_markdown_fonts`), under the same keys.

Progress, and what is left, are tracked on [#15](https://github.com/szaghi/figure/issues/15) (P15), not here.

## Modules

- `figure_markdown`: the public API on the Fortran path (`ig_markdown` over the renderer, `markdown_view_object` over
  the views; `load` reads the file with Fortran's stream I/O).
- `figure_markdown_render`: imgui_rich_md's renderer (`internal/rich_md_renderer.cpp` and its `MarkdownRenderer`, as
  FIGURE configures it): text wrapped word by word, headings and their slugs, emphasis, code spans and blocks, lists,
  quotes and admonitions, tables, images (PNG and JPEG files, never a URL), links reported, imgui_rich_md's HTML tags,
  the selection and its menu; in a document, its headings, blocks and search matches.
- `figure_markdown_document`: imgui_rich_md's documents (`BeginDocument`, `EndDocument`: the table of contents, the
  scrolls, scroll anchoring, the find bar, the scrollbar's ticks) and the views behind `markdown_view_object`.
- `figure_markdown_search`: imgui_rich_md's `FindMatches` (case and diacritics folded, whole words).
- `figure_md4c`: md4c's types, constants and `md_parse`.

## Tests

`src/tests/fortran/figure_test_markdown_frame*.F90`, built by the `-fortran` modes: each case draws the same text or
document with imgui_rich_md (`figure_markdown_ref`: the current path's module under another name, generated by
`scripts/gen_implot_ref.py`) and with the Fortran implementation, in one headless program, 40 frames apart, each in a
window of its own at the same place; the state of every frame (the cursor around the text, the link clicked, the
search's matches) is compared to the bit and the first and last pictures with `test_compare_image(threshold=2,
max_failed=0)`. The existing Markdown tests (`figure_test_markdown` with its golden, `figure_test_layout_view`) and
the recordings (`cb_markdown`, `tut25_editor`, `tut26_clip`) run on the Fortran path in the `-fortran` modes.

imgui_rich_md's behaviours are kept where FIGURE's tests could see them: a broken image draws nothing on its first
frame and an empty image from the second; an HTML chunk that is a prefix of a tag matches it (`strncmp`); an unclosed
`<details>` goes on into the next text.
